This Website

User Experience Web Development
Role Designer / Developer
Timeline June 2026 – Present
Tools Netlify, Git, Claude, Claude Code, HTML, CSS, Javascript

Overview

For the past month or so, I sought to eliminate my need for Squarespace as a platform for my portfolio. I had used it on and off for years, and it was never what I wanted. The way to do that, I felt, was to learn some HTML and set up a workflow with Claude and Claude Code to create a personal website where I can feature both my work and my thoughts. This page covers the development of the website and will continue to be updated as I add more to the site.

.LANG-ing the Foundations

Not being a web-head by trade - I wanted to avoid costly overhead as it pertained to any kind of Content Management System site, Claude Token usage, and overall site performance

I was done with Squarespace or anything like it, had learned to be more proactive in what Claude utilizes tokens for in other small projects, and I have seen too many websites over my years on the internet that prefer to bogged down by popups or flashy performance animation that displays how inconsiderate they are towards the user.

After a few back and forth sessions with Claude, we decided on the following Tech stack:

  • HTML
  • CSS
  • Minimal JavaScript

And finally hosting the site on Netlify via GitHub and established two environments - Development and Release - to avoid releasing content early without testing.

The Markdown (MD) Stack

I am also self aware in that I know I have a tendency to go off on design tangents, nitpicks, and need to reign myself in. So in an effort to keep myself on track, and my work documented, Claude and I built out a few MD’s to assist production and development.

  • REFERENCE.md for project decisions and session handoffs
  • DESIGN-SYSTEM.md for design tokens
  • COMPONENTS.md for component specs
  • PROMPT-GUIDE.md to control what context got loaded per task type

Architecture and planning happened in Claude while implementation and git operations were handled in Claude Code running in Visual Studio. The docs were utilized and referenced via prompts and were the only thing that had to survive the handoff between the two.

Information Architecture

My initial goal was to build the following:

  • Home Page
  • About
  • Standard Page Template for Entries

I decided on accessible Color, Spacing, Motion, picked a typeface (Noto Sans) for wider localization capabilities, had a decent set of Components made in Figma and a Standard Page template all working somewhat effectively in Desktop, Tablet, and Mobile breakpoints.

However, when you are developing a site that reflects your principles - you get nit picky, and you start to repeat “Not good enough” to yourself. It also helps to step away from your desk long enough to realize how similar something is to another thing you’ve seen before. Could be the color or the shape.

As a result of just having the basics - the site didn’t feel like me yet.

Thoughts

I could have stopped there, but instead - I decided I wanted to create a space to express my Thoughts.

This was arguably the largest site based architectural change I made. While it has taken longer to set up, I don’t regret the time spent fixing things up, learning how to utilize browser inspection tools and the console. Do I think it’s perfect? No, but it’s a solid foundation.

  • Home Page
  • About
  • Archive - Work, Thoughts, etc

To get around the CSM or any kind of server, a single static Json file functions as a lightweight database. Every Work and Thoughts entry is referenced in a singular file and Javascript fetches and allows the user to sort and filter as they so choose. Fast and efficient for what I need right now.

Accessibility

As it stands right now, my site has the following currently implemented:

  • Keyboard & Focus
  • Screen Reader / Semantic
  • Visual / Contrast
  • Motion

As time goes on, I will introduce more accessibility options to the site.

The Future

Next up for me is to add more features, accessibility, performance tweaks, adding juice to interactions and of course to write and post new projects. Stay tuned y’all!
