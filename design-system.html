Section 13 — Code Block

Background uses --color-code-bg (background-subtle). Left border uses --color-code-border (accent-primary). Monospace font. Inline code and block pre/code both styled.

Use aria-current="page" on the active nav link after injection to mark the current page for screen readers.

/* Set aria-current on the matching nav link */
function setActiveNavLink() {
    const page = location.pathname.split('/').pop() || 'index.html';
    document.querySelectorAll('.nav-links a').forEach(link => {
        link.toggleAttribute('aria-current',
            link.getAttribute('href') === page
        );
    });
}

Section 22 — Video Embed

Added 2026-08-31. .video-embed — the pattern for embedding video (e.g. YouTube) anywhere on the site, entry pages included. Wraps the <iframe> in a container sized with CSS aspect-ratio: 16 / 9 and border-radius: var(--border-radius-md), matching the in-body image treatment in Section 10. The iframe itself keeps its width/height attributes as a fallback for browsers without aspect-ratio support, but is absolutely positioned to fill the wrapper — CSS governs the actual display size, so it scales fluidly at all breakpoints instead of rendering at a fixed 560×315. Use the privacy-conscious youtube-nocookie.com embed domain, standard controls, no autoplay. Shown unframed below, as it would appear in .standard-page-content on a real entry page.

Section 23 — Video Demo

Added 2026-08-31. .video-demo — a GIF replacement for local UI/bug-demo recordings (Section 22's .video-embed is for third-party embeds like YouTube; use this instead for anything self-hosted in assets/videos/). Unlike .video-embed's fixed 16:9 wrapper, there's no forced aspect-ratio here — demo clips vary in shape (square, portrait mobile capture) — so sizing comes from the <video> element's own width/height attributes, the same intrinsic-size CLS-prevention pattern required of <img> (DESIGN-SYSTEM.md §11.7), constrained to max-width: 100% within the column. border-radius: var(--border-radius-md) matches .video-embed and in-body images for visual consistency across media components. A poster attribute is required on every instance — it prevents a blank flash before the video decodes, and doubles as the static reduced-motion state.

Reduced-motion behaviour: the CSS reduced-motion block at the bottom of style.css only kills transitions/animations — it has no effect on <video> autoplay, so this is handled in script.js instead. On page load, autoplayUnlessReducedMotion('.video-demo video') checks matchMedia('(prefers-reduced-motion: reduce)'): when it's not set, autoplay is added and the video loops silently, GIF-equivalent. When it is set, nothing is added — the video sits on its poster image with native controls, and only plays on an explicit tap/click. That's the capability this component exists to add over a plain GIF. The function takes a selector, so it's reusable for any future autoplay-capable media, not a one-off inline check.

This page loads no script.js by design (see the file-level comment at the top), so the example below shows the markup pattern only — autoplay is not applied live here the way it would be on a real page. The src/poster paths are illustrative placeholders, not a real asset, so playback itself can't be verified on this page either.

Section 24 — Inline Link

Added 2026-09-02. .link-inline — for links embedded mid-sentence in body copy (hero subtitle, entry body text). Underlined at rest, not just on hover, so it reads as a link independent of colour alone. Trailing open-link icon at var(--icon-size-sm), inline with the text. No touch-target padding is added — an inline link within a running block of text is exempt from the 44px minimum under WCAG 2.5.5 (Target Size, AAA), unlike a standalone link such as Section 25's CTA Link. Not yet applied anywhere real — this is a visual reference only, for review before it replaces any existing plain-text inline links (e.g. the hero subtitle's "Christopher Klein" link) in a follow-up task.

Christopher Klein has 13 years within game development, and this example inline link shows how .link-inline sits inside a normal paragraph, at the site's default body line-height.

Flag for review: the icon is built at var(--icon-size-sm) (14px) per spec. Against 16px body copy this may read slightly large next to the text — var(--icon-size-xs) (12px) is the first thing to try if it looks oversized once reviewed in context.

Section 25 — CTA Link

Added 2026-09-02. .link-cta — the real, visible, keyboard-focusable link on every card now, replacing .card-block-link in that role (see Section 14). Underlined text link, no border/background/button chrome — but padded with invisible padding (offset by an equal negative margin so the visible text doesn't shift or add extra gap in the card layout) so the full clickable/tappable area meets the 44px minimum touch target per WCAG 2.5.5, since — unlike Section 24's Inline Link — this link stands alone rather than sitting inline in a run of surrounding text. Trailing open-link icon at var(--icon-size-md). Text content is driven by entry type: "View this work" for Work entries, "View this thought" for Thoughts entries — never hardcoded per card. aria-label carries the full descriptive string ("{Title} — {action}").
