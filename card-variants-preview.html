Final Card Design

A single final card candidate, built against real entries pulled live from data/archive-entries.json. This page's job is now to validate one responsive design at both frame widths, not compare alternatives — the earlier five-variant gallery and both "v2" sections have been removed. Dev/design reference only — isolated the same way preview.html is: not linked from nav, footer, or any live page.

Investigation — confirmed before this change: buildCard() in script.js (the function that renders every live Archive/Home card) builds .card-content in the order Title → Excerpt → Tags → Meta → CTA. The reorder below (Title → Tags → Meta → Excerpt → CTA) is new and applies only within this preview page — script.js and the live .card markup are untouched. Also reconfirmed: the real .card border is 1px solid var(--color-border-default) by default (grey on real :hover, via --color-border-strong — the teal hover here is new, preview-only); .card-image is a <div> with background-size: cover, not an <img>.

New token: --card-image-column-width: 42% was added to :root in style.css (a real site-wide token, not preview-only) and documented in DESIGN-SYSTEM.md §4.5. The horizontal layout below references it instead of a hardcoded percentage.

Responsive breakpoint: horizontal (image-left) layout applies at 768px and above — desktop and tablet, superseding the earlier 1024px decision. This holds because .container's padding (what Archive cards actually render inside) doesn't shrink until below 768px — it's the same --space-8 at both desktop and tablet widths — so the single desktop/tablet frame below (1136px) validly represents both ranges without needing a third frame. Vertical/stacked layout applies only below 768px (mobile).

Horizontal width constraint: the card must never exceed the site's real content column width. .pv-card-final { max-width: 100% } is the explicit backstop, but structurally this already can't happen — the card is a block element filling its wrap, and the desktop/tablet frame (.cv-frame--desktop) is itself calc(var(--max-content) - (var(--space-8) * 2)) = 1136px, the same inner width .container gives real Archive cards today.

Frame widths: the mobile frame is a hardcoded 375px (iPhone SE width, per the original spec — not a design token, flagged here as required by Rule 6). The desktop/tablet frame uses calc(var(--max-content) - (var(--space-8) * 2)), derived entirely from existing tokens.

Interaction: card CTAs and block-links keep their real href values (unmodified, for fidelity) but a page-local click guard below prevents navigation so you can measure without leaving this preview.

Entries: the same two real Work entries used throughout this page's history — Star Engine and Test Framework — shown in both Default and forced-Hover states (mouse :hover also works, but automated measurement and screenshots can't trigger it, hence the forced class).
